# Backlog

Do NOT build these unless I ask. Just make sure nothing in the architecture blocks them.

- Dual-pane view (two folders side by side as a permanent layout; split view in Step 09d covers part of this).
- Workspaces: save whole sessions (all tabs, groups, layout) by name, beyond saved groups.
- Detaching a tab into its own window, and moving a tab group to a new window.
- Full-text search inside images and scanned PDFs everywhere, using the OCR cache.
- Plugin API for community file handlers, themes, converters, and commands; later a community gallery for setups and themes.
- macOS and Linux ports.
- Recorded actions and automatic folder rules (for example "sort new Downloads by type").
- Remote locations (FTP/SFTP, network storage) through a permissively licensed library.
- Send to phone over Wi-Fi (LocalSend protocol).
- Pen and touch improvements (pressure for drawing and signing, touch-sized layout).
- One print dialog with preview for every file type.
- Option to replace the Windows Explorer for Win+E and "open folder".
- Natural-sounding read-aloud voices (Kokoro, Apache-2.0) as an optional pack.
- Sensitive-data warning before sharing (ID numbers, card numbers) as an optional privacy feature.
- A spelling language per document in the text editor (Step 06a uses the webview's built-in checker, which follows the languages installed in Windows; a per-document choice needs a permissively licensed checker or a WebView2 option).
- Update channels (stable and beta) and one-click rollback to the previous version.
- Code signing of releases (only if users ask; see Step 08c).
- Submitting releases to winget.
- Editing files inside an archive (save back into the archive), other view modes inside archive tabs, and Replace/Merge choices when extracting (Step 09f's conflict window could offer them).
