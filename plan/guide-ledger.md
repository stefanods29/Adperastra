## Traps found while writing guides

- Ctrl+Shift+digit shortcuts must read the keyboard event's `code`; its `key` is a symbol that depends on the keyboard layout.
- React's wheel prop is passive: listeners that must stop scrolling are added natively with `passive: false`.
- jsdom has no layout (`clientWidth` and `clientHeight` are 0) and no `ResizeObserver`: components that measure need a fallback size, and tests rely on it.
- The `@tanstack/react-virtual` mock in the UI tests draws every item; `getItemKey` is part of the virtualizer's measurement cache key (a new layout needs a new `getItemKey` function to re-measure).
- A test that checks a placeholder (`pending` commands, "arrives later" texts) must be replaced by the guide that builds the feature, with the new assertions written out. Guides never just delete a test.
- Adding an id to a union used as a `Record` key (for example `ViewModeId`) breaks every record keyed by it at compile time: the guide must add every record's entry, and every test that lists the ids literally, in the same task.
- `samePath` does not ignore a trailing backslash (`C:\F` vs `c:\f\` differ); folder comparisons use `folderViewKey` (05a). Item paths from listings start with `\\?\` (they are built from the canonical folder path); the Explorer's location path does not.
- The Explorer has one location, one listing and one selection. A view that shows several folders (Column view) keeps the open folder as the "active" part and loads the others itself; it must never call `goToFolder` for the folder already open (`goToLocation` empties the list and the same location never reloads).
- Per-folder view memory and multi-folder views interact: opening a subfolder from Column view must not switch to that subfolder's remembered or default view (05b's trail rule).
- A component that changes role in place (a side column becoming the active one) must keep its React key and element, or a double-click lands on a new element and acts on the wrong row.
- `startListDir`'s `cancel` stops polling; before 05b T1 the Rust job then stayed in memory. Anything that starts many listings must cancel them (05b's `useColumnListings`).
- `ExplorerHome`'s `pendingSelectRef` selects an item once the folder has loaded; it is the way to "open folder X and select Y".
- Moving a component to another place in the tree remounts it (React matches children by position and type). Layout features keep fixed child slots (render nothing instead of leaving an element out) so the Explorer and file tabs keep their state.
- Microsoft names never appear in the UI (R-LIC-5): v1's "Office classic" preset is "Classic". Check v1 feature names for trademarks before turning them into labels.
- Two settings changes made by two `onApply` calls in a row lose the first (each call starts from the old settings). A control that changes two sections (layout and `explorer.details_pane`) reports both in one callback.
- jsdom has no layout: tests can check classes, roles and text, never positions; positions are checked by hand and in screenshots.
- `measure-ui.mjs` drives the UI only through the page: give controls that scripts must reach a stable `data-*` attribute (labels change with the language).
- CSS variables defined only on `:root[...]` do not reach a nested preview; theme previews need their own selector (`[data-theme-preview]`).
- Page zoom changes `devicePixelRatio`, so JavaScript conversions stay right, but Rust conversions that use only the window's DPI scale must also include the UI scale.
- A virtualizer does not re-measure when only `estimateSize` changes; give it a new `getItemKey` function when sizes change (the test mock ignores it).
- `transition-duration` forced on every element would animate everything (the default `transition-property` is `all`); to reduce motion, shorten animations, and remove transitions only when animations are off.
- The tokens test imports theme files as JSON: renaming a theme file breaks it. Theme ids equal file names.
- A window-level shortcut listener also sees keys a focused control already handled (CodeMirror's Ctrl+Z): check `defaultPrevented`, or the action runs twice.
- `FileTabView` renders the view with `key={phase.token}`: anything that gets a new token (reload, path change) remounts the view and drops its state; ask before that when there are unsaved changes.
- CodeMirror keeps `\n` internally; line endings must be restored on save from a remembered choice.
- Browsers can decode legacy encodings but not encode them; a 256-entry decode table built with `TextDecoder` covers single-byte encodings without a library; multi-byte legacy encodings stay read-only.
- Writing over a user file with a plain rename loses its creation time and permissions; use `ReplaceFileW` (fs-service `replace_contents`).
- A version must be taken before the file changes, but hashing and compressing would slow the save: copy aside first, store in the background (06b `pending/`).
- Showing file content in the UI never goes through JSON: extract to a file and read it through `fileGrant`/`fileUrl` (06b versions).
- A command's help page must exist in the same task that adds the command (the commands test checks every help slug).
- v1 menu names often carry Microsoft trademarks ("Word document"): the UI says Document, Spreadsheet, Presentation.
- Generated binary files (Office templates) embed the build time: regenerate them only when their texts change.
- Check docs.rs at the pinned version for every library function a guide names; summaries of truncated pages can be wrong (06b found that rumors of "missing" APIs were false, and that blake3's `to_hex` is not a `String`).
- A planned library can need tools the dev PC lacks (liblzma's default build runs bindgen, which needs libclang): prefer pure-Rust crates already in the dependency tree (06d took lzma-rust2, which sevenz-rust2 uses anyway).
- Default cargo features can pull in code a step does not plan for (zip and sevenz-rust2 default to bzip2), a license that needs the owner (bzip2's "bzip2-1.0.6" needed one; allowed since 2026-10-29), or a second version of a crate: give `default-features = false` and the exact feature list.
- `std::fs::rename` replaces an existing file on Windows; putting a new file in place must use `fs_service::move_without_replacing`.
- bsdtar (Windows' own `tar.exe`) writes entries named `./` and `./name`: archive code must drop root entries silently and strip `./`.
- Office files are zips: a handler that lists `application/zip` as a content type would capture .docx files; archive handlers match by extension only.
- Views inside file tabs have no toasts or undo stack: actions that change files from a file tab hand the work to the Explorer through App (06d's `extractRequest`, like `navigateRequest`).
- The test mock of `window` key events: shortcuts registered with `useCommandShortcuts` listen on `window`, so a test can dispatch the key there.
- Windows' deflate cannot compress better than about 1030:1, so a ratio limit of 1000 lets a one-layer deflate bomb through; 06d uses 500 over 1 GiB.
