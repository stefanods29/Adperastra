# Ownership for simultaneous implementation

One worker receives one step and writes in a separate checkout. These rules override historical task wording to modify shared files during concurrent code writing; the coordinator applies those edits.

## Writable feature files

Create only new feature files, tests, styles and bilingual help explicitly assigned by the guide's Files/Tasks/Exact file allocation. Resolve shortened paths using that guide's canonical-definition/data/export table. A crate's src/types.rs belongs inside that named crate, never application src. Do not create an alternative file when the canonical one is specified.

The first producing step in STATUS order owns a new module's creation. Later workers import its public contract and return exact extension proposals for coordinator integration. They do not replace a producer's module, even if its code has not arrived. Their own tests can live in separately named new files. A file assigned to multiple steps is coordinator-owned after its first creation.

Every file already present at source baseline0154c69b3ea5afbfadc39ffa8ee2637733396348 is coordinator-owned during this parallel workflow. Read it and prepare a precise edit proposal. This prevents different worktrees from silently replacing independent edits. New feature modules remain worker-owned until integration; root registration always belongs to coordinator.

## Always coordinator-owned

- Application roots, existing views and registries: App.tsx/main.tsx, native main.rs, ExplorerHome, handler/command/menu/ribbon/settings/help/session registries and existing shared component props.
- Canonical shared declarations and later extensions: settings/tabs/documents/jobs/cache/background/grants/backings/source identity/snapshots/conversion/privacy/transfers/packs/AI/Office/timeline.
- Manifests/lockfiles/features, notices/licenses, asset catalogs/helper entries/build files/capabilities/CSP/isolation allowlist.
- Existing locale JSON and generated pseudo-locale. Return exact English/Spanish keys and values as a proposal.
- Existing scripts/CI, screenshot/version/schema counters, all plan files, CHANGELOG, KNOWN_ISSUES and official reports.

## Exact shared edit handoff

Name path, containing function/type/registry, original baseline or producer revision, exact imports/fields/registration/caller, error/lifetime impact and affected tests. Include a patch when context exists; otherwise use an insertion keyed to the canonical symbol. Do not assume future line numbers or replace large shared roots.

Private map fields, local variables and helpers are not public contracts. Only explicit exports can be imported. Report a missing name to coordinator. Any intentional interface change updates producer, consumers and prompts together.

## Integration

Code writing can overlap across all 54 steps; integration follows roadmap order. Coordinator applies producing declarations before dependent bodies and executes checks per task or recorded reviewed batch. Owner checkpoints block dependent tasks. No unproved capability is registered as working. Coordinator handles all builds/tests/generators and retains local-only Git/no publication restrictions.
