## Goal and honest boundary

Create a password-encrypted container copy, browse it as a virtual folder, edit supported entries without plaintext disk caches, save a new encrypted generation and lock it again. Recovery uses an independently stored recovery identity. Because09f has no proven object-bound recycle-first replacement/removal protocol, originals are retained and existing container replacement is unavailable. The UI must say **Create encrypted copy**, never imply an original plaintext folder became protected. This limitation blocks claiming the original v1 “lock and remove original” flow complete; independent container/virtual editing work is fully specified here.

## Do not do

No customcipher/KDF, password recovery service, plaintext temporaryfiles, “secure erase” promises onSSDs, silentoriginalrecycling, user-selectedcryptographyparameters, cloudsync, AI access, modelcache, shellmount, externalappopenwithout explicitunencryptedcopydisclosure or streamingunsupportededitorsintounsafeCLIspools.

### Pending persistence and dirty-close protocol

E8 `src/services/lockedFolders.ts` persistLockedSnapshot(request:LockedPersistRequest)->Promise<JobHandle<LockedPersistResult>>, native locked_persist_start(request_id,request).
