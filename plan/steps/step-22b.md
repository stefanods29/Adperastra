## Goal and exclusions

Choose one of eight fixed presentation styles, import styles from owned templates, and review structured AI outlines, additions, shorter text, notes and layout suggestions. The app uses real layouts and typed Office operations. Every generated result is a draft or an explicitly accepted change with Undo. Selected assistant backends follow one-shot API payload consent; the model never draws slides.

## Decisions

- D1. A style is bounded data: one DeckTheme, fixed layouts, density and display-only writing guidance. Built-ins are read-only application assets. Imported styles copy safe normalized theme data into app state; source template is never altered and its text, notes, images, scripts, macros, links or active objects are not imported.
- D2. Exactly eight built-ins below, each with its own stable IDs, palette, font configuration, density and all eight layout records. Fonts use licensed bundled Inter regular400/bold700 asset IDs `inter-regular`/`inter-bold` supplied by approved font inventory. If unavailable, card is visible but Apply is disabled with a clear missing-font reason; do not silently select a Microsoft font or download one. Native engine validates embedding permission separately for save/export.
- D3. All themes use720x405pt default16:9. Applying a style to a differently sized deck preserves the current slide dimensions and scales layout rectangles by current_width/720 and current_height/405 before the transaction; text sizes scale by min of those ratios, clamped8-96pt. Do not change slide aspect ratio merely by switching style. Explicit Slide size action remains22a.
- D4. Match placeholders by their semantic role, not filename, translated style name or current coordinates. Existing manual formatting is preserved. Objects with no match remain in place. No user text is deleted or shortened to fit guidance. Overflow/missingfonts produce a review panel with Apply/Cancel; if no warnings, a card's Apply action makes one engine transaction and one Undo toast.
- D5. Library opens as a560px panel,maxviewportminus32, cardgrid2columns with16pxgap, card248x180px including216x121.5preview, 2pxselectionaccent, style name anddensitytext. At width<600px onecolumn. Preview generated onlyfromsyntheticlayoutlabels,noactiveuserdocumentcontent. Search style names localonly. ## AI decisions

1. **A1. All actions.** Create slides from a document/outline/notes; add a slide about a topic; shorten selected slide text; write speaker notes; suggest a better layout; suggest one of the eight styles. Every output is structured outline data, never slide images, SVG/HTML, coordinates, scripts or Office XML. A model-selected style/layout is a proposal, not an automatic switch.
2. **A2. Input limits.** At most24000Unicode source scalars per request,30newslides,32paragraphs/sourcechunk,8selectedimages,4000scalars selectedslide text and8000scalars notes. Split a longer document into explicit user-selected sections, not an unattended whole-document loop. Output at most30slides/128KiB, sourcecitations≤64 and no more than1000typed operations. Existing decks≤10000slides retain22a caps.
3. **A3. Provider consent.** All reasoning uses17a selected assistant backend. Local sends nothing. API uses native exact-payload preview, provider/model display and separate one-shot Send consent for visible source excerpts/images; no consent inferred from enabling AI, choosing a style, local chat history or a prior request. Editing scope/prompt/provider invalidates consent. Sensitive/unlocked inputs refuse API. Retry is explicit and requires a new payload preview where content/provider/model differs; no cloud fallback or automatic paid retry.
4. **A4. App placement.** The app maps each approved outline slide's layout_kind to the selected DeckStyle's fixed real DeckLayout. Title/body/bullet/caption/notes data enters typed DeckTextParagraph/DeckShape/set_notes operations. It chooses placeholder geometry/font/palette from the manual tables, not model numbers. New shape IDs are native/application-owned UUIDs, never source/model IDs. Blank layouts get no invisible placeholders. No text is silently cut to fit; actual clone overflow disables acceptance until user edits or chooses a compatible layout.
5. **A5. Style density.** Prompt gives exact max_bullets/max_words_per_bullet from chosen DeckStyle. A soft guideline violation shows per-slide warning and editable outline, never drops bullets. Minimum readable text16pt except footer10pt. Layout cannot shrink text below that minimum or grow beyond existing96pt cap to hide overflow. Existing manual formatting/unmatchedobjects remain preserved by22a when switching styles.
6. **A6. New draft safety.** Create-from-source starts a cancellable in-memory20a E23draft job with one blank slide and the selected style. Await its completion OfficeDraftHandle; initial revision/saved_revision are1 and content IDs equal. The accepted generated transaction makes the draft dirty. Capture its context, bind generated typedoperations to that draft, and evaluate E21onclone. Human Accept E22 commits one undoable transaction, then opens the draft tab and shows existing Undo toast. The source document/deck remains unchanged. Save a copy chooses a separate destination and leaves the draft source/dirty identity unchanged. Save as new uses09a E12 saveDocumentAsNew(document,destPath)->Promise<JobHandle<DocumentRebindResult>> and E13 DocumentRegistry.applyRebind(result) only after successful no-replace publication; all views rebind atomically. Sensitive draft Save as new refuses until a separate explicit safe-copy route exists. No existing deck is overwritten by generation.
7. **A7. Existing deck actions.** Add uses add_slide_with_id after explicit selectedslide; shorten changes only capturedselectedtextshapes using exactspans; notes uses set_notes forselectedslides; layout uses apply_layout preserve_contenttrue. Build oneproposal/Undo; actual engine clone renders and reports overflow/lostformat beforeAccept. Choosing style afterward uses manual applyDeckStyle/applyDeckTheme oneUndo. Style suggestion merely focuses its librarycard until userApply.
8. **A8. Grounding.** Keep names/numbers/dates/URLs as protected source facts with sourceanchors. Generated text not supported byselectedsource is visibly marked draft/unverified. Speaker notes are private documentcontent, never presenter preview or screenshot bydefault. Imagesuggestions do not fetch assets; selectedlocalimages require image license/sourceacknowledgment, native snapshot and alttext. Never infer sensitive traits in image/alt descriptions.
9. **A9. Evaluation before tuning.** Evaluate prompting with3-5examples per action/style/language and the suites below first. If a style/action fails quality, improve prompts and evaluate again. LoRA is optional only after a retained erroranalysis demonstrates specific gaps; legal datasets/adapterlicense/hardware/cost/provenance must be approved and recorded. No automatic training, no personal documents without explicit rights/consent, no APItrainingendpoint, no weights/adapters inGit. Release.** v1.0 original AI-inclusive milestone requires all prior roadmap acceptance, the20a enginechoice/evidence, eight-style EN/ES deckquality and preservation, actual security/performance/accessibility tests, no touchedBlocker/Major and ownerchecks.
