# Pitfalls (mistakes that already happened here)

Each item happened in this project or is a known trap of this exact stack. Read them before every step. The fix column is the only accepted way.

| ID | Trap | What happened | Do this instead |
|---|---|---|---|
| P-01 | Tauri `Channel` | Under the isolation pattern, `Channel` messages never reach the UI (Step 02: Rust sent 57 items, the UI received 0, no error). | Long work: `_start` / `_poll` / `_cancel` commands (`plan/conventions.md` 3.2). Push notifications: `app.emit` + `listen`. Never `tauri::ipc::Channel`. |
| P-02 | Command not reachable | A new command was missing from the isolation allowlist: it failed silently (KI-007). | Add every command to `generate_handler!` and `ALLOWED`. `npm run lint:ipc` (in the gate) checks it. |
| P-03 | Wrong argument name | The UI sent `language`, Rust expected `lang`: every help call failed (KI-006). | TypeScript keys are camelCase of the Rust parameter (`new_name` gets `newName`). `npm run lint:ipc` checks literal argument objects; always pass a literal object to `invoke`. |
| P-04 | React `ref` never attached | A measurement `ref` was created but never put on the element, so the feature silently did nothing (KI-007). | After adding a `ref`, add a test or a dev check that it is set (`expect(ref.current).not.toBeNull()`). |
| P-05 | Webview default menu | Right-click on an empty area showed the webview's own menu; its Refresh reloaded the whole app (Step 03a Blocker). | Keep the global `contextmenu` handler in `App.tsx`. Every new area that should have a menu opens our `Menu`; text fields keep the default menu. |
| P-06 | Page text selection | Ctrl+A selected all of the app's text instead of the files. | UI chrome has `user-select: none` (existing CSS). Ctrl+A is handled by the view that has focus. Only document content (text viewer, help) is selectable. |
| P-07 | Replace destroyed data | "Replace" deleted the existing item before the new copy was safe (Step 03b review, Blocker). | R-SAFE-2/3: write `~name.partial`, then recycle the old item, then rename the new one in. Test: cancel in the middle leaves the original untouched. |
| P-08 | Permanent delete by accident | A drag-out "move" deleted sources for good (Step 03b review). | Only the explicit "Delete permanently" command deletes for good. Everything else recycles. Search your diff for `remove_file`, `remove_dir_all`, `delete_permanently` before committing. |
| P-09 | Display names are not paths | Restoring from the Recycle Bin matched display names; with "hide extensions" on, `report.txt` showed as `report` and never matched. | Match by full original path (the bin's `$I` record), never by display name. In general: never compare names shown on screen with real names. |
| P-10 | Huge IPC responses | The first poll returned all 196 batches at once; parsing the JSON delayed the first paint past 1 s. | Cap every response (`MAX_POLL_BATCHES` = 8 x 512 items; keep any JSON response under about 1 MB). File bytes never travel as JSON: use the `adpfile` protocol (Step 04a). |
| P-11 | `\\?\` paths | `fs::canonicalize` returns `\\?\C:\...`; the UI showed `C:\...`; unpin compared them and never matched (Step 02 review). | Compare with `samePath()` in TypeScript and normalized forms in Rust. Show with `displayPath()`. Store paths exactly as the user saw them unless the recipe says otherwise. |
| P-12 | Partial results that look complete | A listing that failed halfway showed half a folder as if complete. | When work stops early, say so: return the error or a `skipped` list, and show the translated "some items could not be read" note. |
| P-13 | Refresh resets the view | Folder-watch refreshes reset scroll and selection. | Replace the item list in one state update, keep the selection by path, keep the scroll position. |
| P-14 | Hand-made pseudo-locale | Hand-edited `pseudo.json` broke ICU plurals. | Never edit `pseudo.json`; run `npm run i18n:pseudo`. |
| P-15 | Self-matching secret check | The CI secrets check found its own search text. | Never write the private-key marker words next to each other in any file. |
| P-16 | Stale schema in scripts | `scripts/measure-ui.ps1` writes `settings.json` with a fixed `schema_version`. | When a step bumps the settings schema, update that block too (`plan/recipes/add-settings-field.md`). |
| P-17 | Build output blocked | Windows security blocks cargo from writing under Documents. | Builds use `CARGO_TARGET_DIR=%TEMP%\adperastra-target` (`gate.ps1` and `package-app.ps1` set it). |
| P-18 | HTML5 drag and drop | `dragDropEnabled: true` in `tauri.conf.json` (needed for files dropped from other apps) means HTML5 `dragstart`/`drop` with `dataTransfer` do not work inside the app. | Internal drags use mouse events and `data-drop-folder` attributes (see `ExplorerHome.tsx`, "drag" section). Files from other apps arrive through `getCurrentWebview().onDragDropEvent`. |
| P-19 | Blocking the async runtime | Disk work inside an `async fn` without `spawn_blocking` freezes other commands. | Always `tauri::async_runtime::spawn_blocking` for disk, CPU, or Windows shell work. |
| P-20 | Locks | `.lock().unwrap()` panics after a poisoned lock; holding a lock during disk work stalls polls. | `.lock().map_err(...)?`; copy what you need out of the lock, release it, then work. |
| P-21 | Command lines from paths | A path with spaces or quotes on a command line can run something else. | `Command::new(exe).arg(path)` or a working directory (`current_dir`), never string-built command lines, never `cmd /c` (R-SEC-7). |
| P-22 | Online-only files woken | Reading file content in background work downloads cloud files. | Check `online_only` (or the attributes) before any background read; skip and show the cloud icon (R-FS-1). |
| P-23 | Untrusted HTML in the app DOM | Rendering file content with `dangerouslySetInnerHTML` lets a file run code or load remote content. | DOMPurify + `<iframe sandbox="" srcdoc>` (R-SEC-4). The only `allow-same-origin` frame is the Markdown viewer's own page; never add `allow-scripts` to any frame. |
| P-24 | Growing monoliths | `main.rs` reached 2,600 lines and `ExplorerHome.tsx` 1,800, which makes every change risky. | New code goes into feature modules (`plan/conventions.md` section 2). |
| P-25 | Tests weakened to pass | A failing test is the most useful signal you have. | Never delete, skip, or loosen a test. Fix the code, or stop with `BLOCKED.md`. |
| P-26 | Guessing APIs | Calling a library function from memory that does not exist in the pinned version. | Use the code in the recipe. If the compiler says a function does not exist, stop with `BLOCKED.md` (golden rule 4); do not try other libraries. |
| P-27 | Custom protocol URL | On Windows, a custom scheme `adpfile` is served at `http://adpfile.localhost/...`, not `adpfile://...`. | Build URLs with `fileUrl(token, name)` from `src/services/files.ts` (Step 04a). The CSP lists `http://adpfile.localhost`. |
| P-28 | Timers and listeners left running | A view that polls, listens, or sets intervals keeps running after its tab closes. | Every `useEffect` that starts something returns a cleanup that stops it (cancel jobs, unlisten, clear intervals, revoke file tokens). |
| P-29 | Replacing a whole file blindly | A recipe that replaces a whole file can wipe a fix made after the recipe was written. | Run the recipe's guard command first (`git hash-object <file>` or `git log --format=%s -- <file>`). If it does not print exactly what the recipe says, stop with `BLOCKED.md`. Never merge by hand. |
| P-30 | Two copies of CodeMirror | npm can install a second `@codemirror/state` or `@codemirror/view`; the editor then fails with "Unrecognized extension value". | Install the exact versions the recipe gives. `npm ls @codemirror/state @codemirror/view` must show one version of each; if not, `npm dedupe`. |
| P-31 | "Read-only" editors | `EditorState.readOnly` stops the user's typing, but code that dispatches changes still changes the text. | Viewers dispatch changes only to load the file's text. Saving is only the editor's explicit Save (Step 06a). |
| P-32 | Line endings in .ps1 files | `.ps1` files use Windows line endings (CRLF, `.gitattributes`); the recipes show them with plain line ends. | Match a "find exactly" block line by line, ignoring the line-end characters. Never convert a whole file's line endings. |
