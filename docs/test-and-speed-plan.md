# Test and speed-measurement plan (Step 00)

Implements `plan/git-and-testing.md` and `plan/speed.md`. No test code exists
yet; harnesses are built incrementally from Step 01b on. One command runs
everything: `scripts/test-all.ps1` (created when the first suite lands), with
`--quick` (minutes; before every push; also on GitHub for every push) and
`--full` (on the `testing` branch before anything reaches `main`; shorter
fuzzing weekly on GitHub).

## Speed measurement

- Machine: `docs/benchmarks/MACHINE.md`. Corpus in `test-files/`, generated by
  scripts (nothing large is committed): text 1 KB to 2 GB; images to 100 MP;
  PDFs of 1/100/1,000 pages plus a scanned one; MP3, 1080p and 4K video; a
  10,000-entry archive; Office files (10- and 100-page documents, a
  100,000-row sheet, a 50-slide deck); a generated 100,000-item folder.
  Owner-provided real files are requested in the Step 00 report (Q3).
- Every benchmark run records time-to-first-view and time-to-ready per item
  plus the core interactions (app start, folder open, tab switch, search
  keystroke), writes one small JSON per run into `docs/benchmarks/`, and the
  step report tabulates interaction / tier / measured / pass-fail.
- Tiers (`plan/speed.md`): Instant 0.1 s, Smooth 16 ms/frame, Fast 1 s,
  Waiting-with-feedback 1-10 s, Background job over 10 s. A slowdown over
  20% versus the previous step fails the suite.
