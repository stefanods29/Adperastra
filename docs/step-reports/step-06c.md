## Owner checklist

Use any folder you can write to (for example `%TEMP%\adp-06c`, an empty folder you create) and a second folder with two of your own files for My templates.

1. **New** lists the nine entries with the separator before **From template…**; on the Home page they are disabled.
2. Create each blank kind: each appears with its name selected; rename it; Ctrl+Z sends it to the Recycle Bin; Ctrl+Y brings it back.
3. Create two Markdown notes: the second is "New note (1).md" (new items count from one). Double-click a `.md`: it opens in a tab and can be edited. Double-click the `.docx`, `.xlsx` and `.pptx`: they open in their Windows apps (or Windows asks which app) and show an empty document.
4. **From template…**: six templates with descriptions. Create each: the Budget and Invoice add up when numbers are typed in their Windows app; the Meeting notes open in a tab.
5. Switch the app to Spanish: the window, the template names and the files' contents are in Spanish ("Carta.docx", "Notas de reunión.md").
6. **Choose folder…** your second folder: its files appear under My templates; create from one: a copy appears; the original is unchanged. **Open folder** shows that folder. Rename the folder in Windows Explorer and reopen the window: the missing-folder note and **Change folder…**.
7. Restart the app: the My templates folder is remembered.
8. Repeat checks 1 and 4 in the dark theme.

## What works

- The New menu (command bar and the right-click menu) creates New folder, Text file, Markdown note, CSV table, Document, Spreadsheet and Presentation, and opens **From template…**. All entries are commands, enabled only while a folder is open.
- Markdown and CSV files are created empty; the Office kinds are copies of three blank files shipped with the app. Every new file gets a translated, unique name, an undo entry (Recycle Bin and restore), the "Created …" toast and its rename box open; nothing opens by itself.
- Six built-in templates in English and Spanish (letter, report, budget, invoice, meeting notes, simple presentation), generated by `npm run templates` from the `templates.*` texts of the translation files, so their words are translated too. Budget and invoice carry real formulas.
- The template window lists the built-ins with a file tile, name and one-line description, and My templates from the folder chosen with Windows' folder picker. One selection across both lists, arrow keys, Enter or a double-click to create, **Create**, **Cancel**, **Choose folder…** / **Change folder…** and **Open folder**.
- My templates: the chosen folder is stored in settings (schema 11), remembered after a restart; every file directly in it (not hidden, not system, at most 200, natural name order) is a template and creates a copy under its own name.
- Creating from a template writes `~name.partial` and renames it into place, clears the Read-only attribute on the copy, and never replaces an existing file (the new one gets a number, like "Carta (1).docx").
- Rust copies only from the shipped `builtin` and `blank` folders or the chosen My templates folder (`templates.not_allowed` otherwise), so a path from the page can never copy an arbitrary file.
- Help pages `templates` in English and Spanish.

## Not in this step (on purpose)

- No Office viewers or editors (Steps 13, 20b, 21a, 22a): Office files open through the open pipeline, which sends them to their Windows app today.
- No template editor and no template variables. No sub-folders inside My templates.
- No New entries for other file types (images, archives); archives get "Compress to…" in Step 06e.
- `docx`, `exceljs` and `pptxgenjs` are development tools only: the app never runs the build script and never ships those packages.
- No Microsoft names in the app: the menu says **Document**, **Spreadsheet**, **Presentation**.

## Decisions and plan changes made during the step

- **Unique names count from one.** The guide's examples said "New note (2).md" / `Letter (2).docx`, but `fs_service::unique_destination` counts from one and the owner decided that in Step 03b. The guide (D2, the T4 test and both help pages) was corrected in `docs(plan): step 06c unique names count from one`; the code and the help pages use "(1)".
- **Measurements and screenshots anchors.** `measure-ui.mjs` has no hard-coded step value (the step id is its ninth argument; see KI-039), so T7's first item had nothing to change. Step 06b's measurement and screenshot blocks are not in this worktree (parallel work), so the "command bar New menu (with templates)" measurement was added after Step 06a's measurements and `44-new-menu` / `45-template-window` after Step 06a's screenshots, before Step 06d's. The guide says so in `docs(plan): step 06c measurement and screenshot anchors`.
- **`Dialog` gained an optional `className`** (`src/components/Dialog.tsx`) so the template window can carry the guide's `adp-templates-dialog` class and widen the box; every other dialog is unchanged.
- **`templates.css` is imported after `archive.css`** in `src/main.tsx`: the guide says after `versions.css`, which Step 06b creates and which is not in this baseline.
- **`tempfile = "3"` as a dev-dependency of `src-tauri`** for the new module's tests. It is already a dev-dependency of four workspace crates and in `Cargo.lock`; nothing new ships.
- **ExplorerHome passes `templatesFolder` as the dialog's `key`**, so when the chosen folder is saved in settings the window lists again with the new folder.
- **The dialog re-lists right after a folder is chosen**; `save_settings` is a synchronous command, so the new folder is already in the cache when `templates_list` runs.
